## User objective

Independent `claude-auto` and `claude-openai` sessions discover each other, coordinate decisions and help finish their owners' tasks. A session with no active owner task helps another session automatically. Help has a separate context and contribution ledger. A submitted owner prompt preempts assistance. Logical membership and task ownership survive context rotation. Test with real sessions; do not install or release the prototype.

## Invariants to demonstrate

- A wrapper invocation has a logical identity distinct from each physical conversation and cache anchor.
- Bootstrap is not owner work. Rotation updates physical identity without erasing the owner's task, decisions or contributions.
- Owner state is explicit: no task, active task, awaiting collaborators, completed, closed. Terminal quiet alone is not availability.
- Help runs in an isolated conversation, with only the delegated task snapshot. Owner conversation receives an attributed result, not the helper's raw transcript.
- A submitted owner prompt fences and cancels current assistance before accepting new work. Late results cannot complete an expired assignment or overwrite a newer owner revision.
- Work claims are atomic, time bounded and recoverable after crashes. Closing a session releases its claims.
- Decisions cite their task revision and record participants, alternatives, rationale and owner acceptance. Peer agreement never grants user permissions.
- Sharing is local, opt-in for the prototype and limited to registered sessions. No automatic messages to unrelated existing sessions, no global settings changes, no production installation changes.
- Tests keep transcripts and artifacts under dedicated directories; cleanup never touches other sessions.

## Approaches under investigation

1. Persistent local registry plus launcher lifecycle integration and native plugin events. Isolated helpers, explicit cancellation, durable claims and decisions. Main uncertainty: installed native API event and cancellation semantics; verify live.
2. Native Agent Teams plus an external continuity adapter. Built-in task claiming and messaging, but official docs state one team per session, no sharing teams across sessions and no restoration of in-process teammates on resume. Does not alone meet the objective.
3. Agent Mail / Beads style durable mailbox and reservations with a custom supervisor. Useful durable task/message pattern, but advisory reservations and messaging alone do not implement owner preemption or isolated idle assistance.

No selected workaround: merely adding instructions to call SendMessage would leave scheduling and interruption unenforced.

## Test design (planned, not results)

Condition groups: wrapper kind (direct/OpenAI), lifecycle (fresh/resume/rotation), owner state (idle/active/waiting), helper state (none/running/completing), incoming event (user prompt/result/crash), assignment revision (current/stale). Test bounded state transitions exhaustively, then select cross-group triples (t=3, INFERENCE: owner state, helper state and incoming event interact in cancellation races). Pair coverage alone does not establish correctness of ordering, process cleanup or model decisions. Real-session scenarios must separately exercise these semantics and preserve logs.
