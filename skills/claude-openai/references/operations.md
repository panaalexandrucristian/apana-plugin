# Operations: load only when needed

## Troubleshooting

- **401/expired auth:** run `python3 <skill-dir>/scripts/claude_openai.py login`, finish the browser flow, then retry verification. Do not force a new login on every install.
- **No models:** `/v1/models` may return HTTP 200 before asynchronous OAuth registration completes. Wait for nonempty registration when credentials exist. Inspect `models`; listing is not proof of entitlement—verify inference. The wrapper prefers listed `gpt-6-astra`, otherwise the first available GPT model; choose an explicit listed model with `--model` or `CLAUDE_OPENAI_MODEL`.
- **Quota:** respect the indicated wait. For account denial, unavailable entitlement or browser challenges, report the blocker instead of circumventing it. Never fall back silently to a paid API key, remote relay, another account/provider or Anthropic model.
- **Repeated models in `/model`:** keep Opus/Fable/Sonnet/Haiku routing, but curate the display with the documented `modelPicker` setting in the launcher's session-only `--settings` file (Claude Code 2.1.242+). Use `replaceBuiltInOptions: true` and one row per exact `/v1/models` ID; put the selected model first. This replaces duplicate family/gateway rows without changing `availableModels`, global settings or helper routing. Claude always retains its separate Default row. Preserve image/review entries unless the user requests filtering. Never patch the Claude binary or remove routing aliases to tidy the menu. On older clients, explain the version requirement rather than silently upgrading. Inspect the real menu and runtime settings; verify all catalog IDs survive, and test both inference and a tool call. Cancel with Escape or use `s` for a session-only test switch—Enter saves to user settings. Catalog entries are remote routing choices, not locally loaded models or proof of inference access.
- **Warnings:** Claude can report an unrecognized GPT model and disable Claude.ai organization connectors under third-party authentication. A successful response envelope and tool execution determine whether the request worked. Claude dollar estimates and `firstParty` labels do not establish an OpenAI API charge.
- **Invisible browser:** inspect the actual native browser with `computer_use`; bring its window forward only when requested. A managed browser or successful `open` return does not prove user visibility. Stop pending login when the user pauses; wait for permission before reopening. Passwords/2FA stay in the provider UI or credential-vault flow, not chat.

## Catalog snapshots and evidence

A **new launcher process** checks the general model catalog, not `codex_client_models.json`. The verified adapter is CLIProxyAPI `8.0.40`, identified from its help banner. Other versions keep existing behavior with a freshness warning; never upgrade automatically or inject assumed-compatible options. The temporary configuration points `models.catalog` to a private absolute snapshot file; `-local-model` still covers the other catalogs. Neither the persistent configuration nor global Claude settings are rewritten. A supervised handoff reuses the same sidecar, snapshot and routing until the launcher exits.

Sources: an explicit nonempty `models.catalog` HTTP(S) URL or absolute file takes precedence and has **no public fallback**. If obtaining/validating it fails on the supported adapter, remove only `models.catalog` from the temporary configuration, so the proxy cannot re-fetch a rejected source outside the launcher's safeguards. Warn explicitly that this launch degrades to the embedded general catalog and valid proxy inventory; preserve the persistent configuration and all other catalog settings. An unknown proxy version retains its existing configuration/behavior with a warning, without claiming these adapter safeguards. `embed`/`disabled` are upstream internal selectors, not valid explicit settings. With no explicit source, try `https://raw.githubusercontent.com/router-for-me/models/refs/heads/main/models.json`, then `https://models.router-for.me/models.json`. A new HTTP opener has no inherited cookies/OAuth/sidecar key or global authentication handlers; legitimate environment network proxies still work. Redirects stay within HTTP(S), and HTTPS cannot downgrade to HTTP. Explicit HTTP remains supported.

Configured safety bounds (chosen, not measured performance; n=6 bounds): total catalog budget **10 seconds** across reads, redirects and fallback; operation timeout **3 seconds**; body cap **4 MiB** enforced during reads; at most **6 requests per candidate** in a redirect chain; startup wait **30 seconds**; source/control IPC cap **64 KiB**. A short-lived worker runs this trusted module with Python `-I`, never downloaded code. The parent owns the deadline, kills/reaps the worker on timeout or cancellation, and removes its private data directory. This bounds even a buffered read that keeps trickling or an operation that never returns to Python; it does not promise real-time OS scheduling/process creation. No signal handler or existing timer changes, and non-main threads work too. Source details travel over bounded stdin, not argv; worker stdout/stderr are discarded, and its environment retains only standard proxy/CA/runtime paths, not provider tokens or the sidecar key. The validated result is a capped UTF-8 data file, not executable IPC. Catalog data lives in its own new empty 0700 directory, in a 0600 file, separate from scripts, and is deleted with the launch directory. No persistent download cache is added.

Launcher validation is deliberately stricter than upstream: complete Codex tier structure, valid nonempty IDs, no duplicate IDs within a section, no duplicate JSON keys or nonfinite values. An explicitly empty tier is valid; a missing tier is not evidence of model retirement. The final `/v1/models` response is validated separately. Default selection remains listed `gpt-6-astra`, else the first `gpt-` ID: this historical prefix rule includes `gpt-image-2`, **not** a conversational-model classifier. Image/review rows remain in the generated picker. Explicit model disappearance, no accepted `gpt-` candidate, a dead sidecar or an unusable API are real launch errors.

Evidence is separated into snapshot validated, refresh batch observed, and final inventory read. For a changed snapshot, the launcher waits for a positive aggregate refresh event containing the exact provider token `codex`, then reads inventory again. That batch does **not** prove publication for every credential: upstream can skip changed/disabled credentials or count a helper that published nothing. The warning remains explicit even after observing the batch. Timeout or catalog failure also continues with valid proxy inventory and a freshness warning; none is proof of retirement or permission to switch account/provider/model.

Only complete ordered raw Codex records equal to the tagged embedded baseline bypass the batch wait. Baseline: `v8.0.40` (`d946c4f`), `internal/registry/models/models.json`, SHA256 `202d50ff901832d8ed915db9a4f852e957ea5c2370b5f8bbfac7db226ba8b7d9`. Reproduce tier fingerprints with `catalog_fingerprints()`; offline fixtures retain the raw tagged records. Array order matters for alias collisions; API/getter output and ID sets cannot reproduce this check. Each process compares against the **embedded** baseline, never the previous launch. Unknown fields or absent-versus-false booleans can change this stricter fingerprint without changing Go-decoded data or producing a callback: bounded wait plus **unconfirmed**, not a verdict that application failed. Baseline equivalence proves only catalog-input equivalence, not account publication or inference.

Generated `modelPicker.options` deduplicate inventory and put the selection first with `replaceBuiltInOptions`. Actual client display is separate evidence: Default/current-model rows remain, managed policy and client validation can prevail, and if no supplied row survives validation the client can retain filtered builtins. Inspect actual rows separately; neither an API/menu match nor successful inference alone certifies catalog synchronization. A real installed-launcher overwrite, OAuth login, inference or tool probe each needs the applicable owner approval; use CLI flags rather than `/model` or `/effort` to avoid saving global preferences. Do not manually patch the plugin cache or synchronize other installations unasked.

## Runtime and preservation

The installer owns `~/.local/bin/claude-openai`, a marked `.zshrc` alias block and `~/.local/share/claude-openai`. It refuses foreign launcher/state files. Private state contains OAuth credentials, local proxy configuration, the installed script and shell backup. Credentials are separate from existing Hermes/Codex logins.

Each Claude session uses a random loopback port and local client key; the sidecar stops on normal exit. Main, helper and subagent defaults route to the selected GPT model. Hooks, project instructions and the existing permission mode remain loaded, including bypass mode if the user already selected it. Never add bypass flags or disable hooks merely to pass a test. Claude-specific cloud features need not work through this bridge.

Uninstall removes only owned launcher/alias content. It preserves credentials, state, shell backup, CLIProxyAPI and the skill. Explain this before removal. Credential deletion/revocation is a separate user decision. Reinstallation is supported.

## Running under claude-auto

Resolve the installed `claude-auto` from PATH, falling back to `~/.claude/claude-auto/claude-auto`. Load it with a non-main run name and read only `passthrough(args)` and the presence of `wrapper`; loading does not start it. For an interactive call (not `passthrough`), run it as `python claude-auto --settings <routing settings> --model <model> <user args>` with `CLAUDE_AUTO_CLAUDE` set to the real `claude`. `claude-auto` merges its hooks into the `--settings` file, appends its rule, sets `CLAUDE_AUTO_RUN` itself (it drops an inherited value), and starts the next session with the same `--settings`, `--model` and environment after a handoff. The sidecar and the settings file therefore must outlive the first session: they belong to the launcher process, not to one `claude` run.

The current extra rule requires enumerating real token variants before writing text matchers/filters, then comparing old/new output on real data and explaining differences. `claude-auto` reads it fresh on each launch. Ordinary global/project `CLAUDE.md`, rules and hooks still load through Claude Code itself; do not duplicate them into the appended prompt.

Keep the source's exceptions: `CLAUDE_AUTO_RULE=off`/`0`, explicit `--append-system-prompt` or `--append-system-prompt-file` (including `=` syntax), and passthrough invocations such as `-p`/`--print`, help/version and subcommands start `claude` directly, as before. Arguments after `--` are literal prompt text. If `claude-auto` is absent, keep the standalone OpenAI launcher usable; if a present source cannot be loaded or has no `passthrough`/`wrapper`, fail explicitly rather than silently dropping the rule and the handoff.

Verify both layers: unit tests for the source lookup, a missing or incompatible source, the exact subprocess argv and environment; then an interactive session with a small `CLAUDE_AUTO_THRESHOLD`-style limit that rotates once and answers on the same GPT model in the new session. Do not use a print-mode run as proof: print mode deliberately bypasses `claude-auto`.

## Offline test portability

Mock executable discovery as well as process/HTTP calls in sidecar unit tests. Run the suite once with CLIProxyAPI absent from PATH to catch accidental host dependencies; only the actual loopback lifecycle integration test may skip for that absence. With the real proxy available, that test mocks the catalog download and sandboxes only the proxy children to loopback on macOS (including their unrelated background metadata lookups). If the binary is present without an available isolation mechanism, it reports an explicit test blocker instead of silently allowing egress or adding a skip. Keep the fake-Claude/real-wrapper handoff outside that sandbox: macOS otherwise blocks its `ps` subprocess. Linux CI passing with a missing-proxy skip does not establish live OAuth or model inference.

## Proxy security: CLIProxyAPI 8.0.40

Consult this section before editing the proxy configuration or changing versions.

- Inference listener: `127.0.0.1`; random local client key. Keep directories 0700 and credential/config files 0600. Never publish credentials, keys, shell backups, full request logs or private transcripts.
- `server.commercial-mode: true` disables request capture middleware. `request-log: false` alone still captures error payloads. Keep dashboard, remote management, discovery, plugins and profiling disabled.
- Keep `-local-model`; the launch-local general-catalog snapshot described above is the explicit exception to embedded-only catalogs. Other explicit catalog settings retain upstream precedence. Do not start the global Homebrew proxy service or install unrelated updates.
- Sanitize the proxy subprocess environment for uppercase/lowercase `HOME_JWT`, `PGSTORE_*`, `GITSTORE_*`, `OBJECTSTORE_*`, `MANAGEMENT_PASSWORD` and `DEPLOY`; these can select remote credential/configuration storage or expose management. Keep its working directory private: startup loads a local `.env`. Do not globally strip Claude's configuration/environment.
- Do not claim OpenAI-only networking: this version fetches Antigravity and Grok version metadata. Reviewed paths perform metadata GETs, not prompt/token uploads.
- Browser OAuth temporarily binds all interfaces on port 1455 despite inference being loopback-only. Use a trusted network. Do not change callback ports as a workaround: the OAuth redirect stays hardcoded to 1455.

## Verification details

Use the bundled unit/integration tests plus actual `verify`, shell alias discovery and an interactive tool call. Unit mock fixtures and a healthy HTTP listener are not real model success. Inspect the JSON envelope even if exit status is zero: require `subtype=success`, no error, GPT model usage and `CLAUDE_OPENAI_OK`. `verification.json` records the last check, not current health. A request must succeed through the intended OAuth route; never synthesize a result.

[Recorded integration results](verification.md) describe prior checks and limits. For a controlled probe, select `--permission-mode manual` and allow only necessary tools. Inspect trust/permission prompts rather than blindly sending Enter.

## Measuring the skill's context footprint

Keep routine instructions in `SKILL.md`; move failure-specific detail here without weakening the bundled installer. Compare actual Skill-expanded text from fresh Claude sessions using identical prompts, model, effort and tools. Require a real `Skill` call and the same usable installation command before/after. Confirm routine installation does not automatically read scripts/references.

For token counts, send each expanded text through the same upstream model with identical fixed wrappers and an empty-wrapper control; subtract that control and include cache-read input tokens. Record usage, model and boundaries. Do not treat characters, dollar estimates, cached-only counts or early streaming usage as exact skill tokens. CLIProxyAPI 8.0.40 falls back to `cl100k_base` for unrecognized model names such as `gpt-6-astra`; its local count endpoint is not authoritative upstream tokenization. The main-file reduction is not a promise to halve total session usage, and opening these references adds their context back.

After edits, check installer/test hashes and rerun the existing suite. Reinstallation, real tool requests and synchronization of other installed copies require separate owner approval. Package only the skill files, never private benchmark transcripts or state.
