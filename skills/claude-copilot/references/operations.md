# Copilot bridge operations

## Trust, prerequisites and installation

Supported baseline: macOS arm64, zsh, Python 3.9+, Claude Code 2.1.316+ and CLIProxyAPI 8.0.40. The client baseline is the tested combination of HTTP model hooks, session/request-class gateway headers and context controls, not a claim that every earlier build lacks them. Unsupported native architectures/builds stop rather than select a different artifact. Install prerequisites separately; the helper neither upgrades them nor starts the Homebrew service.

Native pin (configuration identifiers, not measurements):

- Release: `syepes/CLIProxyAPI-plugin-github-copilot` `v0.1.1`
- Source commit: `596e599671ae66fafa4d5f132de6073edc6da164`
- URL: https://github.com/syepes/CLIProxyAPI-plugin-github-copilot/releases/download/v0.1.1/github-copilot_0.1.1_darwin_arm64.zip
- ZIP SHA-256: `976c5e3398bf8ed99d19f93ddb4094d3fbb17a5fbec39b730ee1f5e74fde3b4b`
- Extracted library SHA-256: `f02b3dfa604c941832b00176c9c6621a24b662d3e24997d5343ce787178f7c27`

The release is mutable; these reviewed hashes are not independent attestation or publisher signatures. Native plugin redistribution licensing has not been established. Apana contains neither its binary nor credentials. Obtain separate explicit consent for local native execution; preserve notices beside the installed library. The installer consumes a local pinned archive, validates all archive members before extracting and refuses traversal, links, duplicates and oversized content. Download into a new empty directory, keep execution scripts separate and use Python `-I` from outside downloaded directories. It deliberately does not fetch `latest` or silently download executable code.

State is `~/.local/share/claude-copilot`; launcher is `~/.local/bin/claude-copilot`. Installation copies the standalone script and manages only its marked `.zshrc` alias. Reinstallation preserves compatible account configuration, credentials and the initial backup. Ownership collisions and links are refused before writes. A failed login/verify leaves an explicitly partial installation, not a success. Run the bundled installer again after updating Apana; an already running session retains its original processes/settings.

## Authentication and privacy

Use `login` only for an explicitly approved device-flow attempt. Existing active credentials are never overwritten by login; replacing/removing them needs a separate decision. The helper follows the host's own nonempty state, respects pending/slow-down and a finite deadline, stops and waits for the dedicated login host before removing staging, then verifies the GitHub identity and asks the user to type the intended account. Only that confirmed credential is promoted. Cancelling does not promise to revoke GitHub grants.

Native hosts receive private cwd/HOME/TMPDIR and an allowlisted environment, an isolated credential copy and only the Copilot plugin. Request logging and usage collection are disabled; commercial mode is enabled. Data, management and guard-control keys are separate. Management is enabled only during login and disabled for sessions. Session directories and files are owner-only. Do not print credentials, request logs, shell configuration or private transcripts.

The client keeps its ordinary configuration directory, hooks, plugins and policies. Routing uses a session settings overlay plus environment; both auth headers and the session apiKeyHelper resolve only to the local data key. Inherited custom Authorization/x-api-key/Host/gateway identity headers are removed while unrelated headers survive. Conflicting explicit routing settings are refused. The guard forwards only its native key and approved protocol headers, not client credentials. Managed restrictions still apply; a hook or authentication restriction can stop the route. The guard is not a sandbox against a malicious local process that can read the same user's files.

## Fresh models, guard and context

Each launch makes new authenticated GitHub identity/token calls and a direct Copilot `/models` fetch, then reconciles it with a cold native host registry. API errors, explicit incompleteness, pagination indicators not covered by the pinned contract or registry differences stop before the client. No cached catalog is used for success. The current API has no documented pagination loop or total: “entire catalog” means its entire response, not a promise of unreported models. Schema/pagination changes need review.

The pinned plugin trims IDs, removes empty/duplicate case-folded IDs and excludes non-chat or policy-disabled entries. There is no family allowlist. Original IDs are retained in metadata and namespaced as `copilot/<id>` in requests/picker. Native cloaking is disabled. Capability failures block the configuration with the model named; they are not silently filtered to make launch succeed. Missing supported_endpoints follows the pinned plugin's chat-completions default; advertised Messages/Chat/Responses use native translation. Capability metadata is not a live inference test of every model.

The guard pins the selected main model per registered session. Only a matching fresh PreModelSwitch/PostModelSwitch pair with explicit command/picker/SDK source can change it. Startup policy substitution, Default resolving elsewhere, automatic fallback and resumed foreign models are refused before native forwarding. Hooks observe the normal confirmation rather than auto-allow it. Helpers stay on the original explicitly chosen model, recognized by the real subagent request class and agent header; another valid catalog ID is still refused for a helper. New handoff sessions inherit the last explicitly authorized main model; the sidecar/settings belong to the launcher, not the first child. A private child launcher reads the guard's authenticated current selection and corrects missing or previously accepted stale transcript model arguments to that selection. Pending, rejected or never-accepted model arguments fail closed. Accepted launch history is not an inference allowlist: main requests still require that session's current model.

Context is a calculated common ceiling over every eligible catalog model: minimum of each reported prompt limit and context limit minus the configured output allowance, capped at the tested client upper bound. Output is the minimum advertised output limit capped at the configured allowance. This is not input+output arithmetic masquerading as context capacity. The client gets `CLAUDE_CODE_MAX_CONTEXT_TOKENS`, `CLAUDE_CODE_MAX_OUTPUT_TOKENS`, `CLAUDE_CODE_AUTO_COMPACT_WINDOW` and `CLAUDE_CODE_DISABLE_1M_CONTEXT`; picker entries contain no invented context/behavesAs fields. Small legacy models can lower the whole session's ceiling substantially; no family is hidden to avoid that result. A prompt/tool set larger than this envelope may fail or compact early. No maximum-length inference guarantee is made.

CLI model wins over `CLAUDE_COPILOT_MODEL`, which wins over `copilot/gemini-4-argon`. Invalid explicit choices never fall back. Arguments after `--` are literal. The last explicit settings file/JSON is merged into one session overlay, preserving unrelated options, permissions and hooks; reserved routing conflicts are errors. `availableModels`, fallback policies and managed policies remain the client's responsibility, with unaccepted inference stopped by the guard.

## Supervisor and lifecycle

A compatible installed `claude-auto` supplies its existing passthrough/rule/handoff behavior. The helper does not import runtime code from `claude-openai` or modify the supervisor. Missing wrapper means standalone; incompatible present source means error. Existing prompt opt-outs remain the supervisor's responsibility. Print/help/subcommands do not demonstrate interactive handoff.

`CLAUDE_AUTO_NEXT_ARGS` keeps its replacement-argument semantics, including nonrouting flags and the last effective settings file/JSON. The adapter validates it before starting a client and rejects conflicting routing/helper settings, a different preselected model and fallback-model flags. Initial and next settings receive the required overlay; each supervised child validates and reapplies it, including bootstrap and children after the supervisor's handoff maximum. The supervisor still chooses which settings apply during bootstrap. User hooks, permissions and managed policies remain in force.

Normal exit, startup failure, Ctrl-C, SIGTERM and SIGHUP unwind the owned guard, native host and temporary session state. Interactive Ctrl-C remains with Claude/the supervisor in the same process group; native and captured processes have separate groups. Supervised shutdown allows handoff grace, both configured kill-wait phases, polling, descendant reaping and an adapter margin for finalization, so valid long waits are not cut short. Negative/non-finite waits or an overflowing combined budget stop before launch; malformed numeric text retains the supervisor's default. No cleanup guarantee is made for SIGKILL, machine failure or OS calls that hang during process reaping or terminal restoration. Uninstall does not stop running sessions and retains state, backups, native plugin and dependencies.

## Evidence and limits

Earlier feasibility evidence (measured, not rerun here): direct Messages tool round-trip and SSE passed (n=2 requests); explicit SDK/TUI switching, startup substitution and resume refusal were exercised against a non-forwarding backend. Real-wrapper interactive handoff passed with a note Read/result/continuation (n=1 handoff, n=4 fake requests, n=0 upstream requests). Live verify passed separately (n=1 Messages sidecar request). These are prototype gate observations, not a claim that the production adapter or every catalog model has passed the same live flow.

Helper continuation on the implementation turn passed (measured, n=1 live helper run, n=3 Messages sidecar requests): main, subagent and continuation all used `copilot/gemini-4-argon`; the result sentinel, session and modelUsage matched. The direct catalog contained n=52 entries and the reconciled registry/picker n=47; non-chat difference was n=1 completion, n=1 image and n=3 embeddings. Comparison of old chat-only and pinned normalization on this same response found no ID difference (measured, n=1 catalog). These counts are observations, not future fixed totals. GitHub rejected the staging script's unsupported API version; the probe was repaired to the version listed by `/versions`. No login or account change was required.

The full catalog's common input ceiling is calculated as 12288 with output allowance 4096 (n=47 eligible entries in that observation); this is lower than the earlier Gemini/Sonnet-only client probe. API metadata and client accounting are distinct. Cost estimates and `firstParty` labels do not establish Copilot charges; sidecar request counts do not count internal upstream retries. Namespaced response/modelUsage matching establishes the adapter route, not independent attestation of the model executing inside GitHub.

During the helper run, global settings snapshots stayed equal but `.claude.json` changed at `pluginUsage` (measured, n=1 snapshot pair, attribution not established); the child ran under read-only global scope. This is not reported as an unchanged complete global profile. Runtime/host/guard cleanup completed. No active installation, shell edit, release, or native redistribution was performed as part of implementation validation.

Pre-correction production-adapter baseline (measured, n=1 sandboxed real-client/fake-backend probe, n=1 fake request, n=0 upstream requests) confirmed the common context ceiling, session registration and bearer/helper isolation despite fictitious inherited auth headers; captured global snapshots stayed equal. This probe predates the offline corrections below and was not rerun on the corrected runtime. This found and fixed a real integration defect: SessionStart supports command hooks, not HTTP. Its private command forwarder is now covered by an actual subprocess test, while explicit model-switch hooks remain HTTP. The real existing supervisor also completed an offline fake-child handoff through the production guard (measured, n=1 handoff, n=2 fake children/requests). These are not live production skill-driven installation or live production interactive handoff evidence; those remain unrun.

Offline correction evidence: the real-supervisor/fake-child NEXT_ARGS regressions changed from failure to success (measured, n=3 test methods, n=27 failing subcases before repair, none after). Accepted-switch handoff now passes with transcript model A, B or missing, alongside pending/rejected-switch negatives (measured, n=12 source/transcript subcases). SIGHUP initially left owned processes holding captured pipes; the signal unwind repair passed teardown and process-group checks (measured, n=6 signal × standalone/supervisor cases across HUP, TERM and terminal-group INT). A follow-up review found the adapter's fixed wait could kill the supervisor before it escalated against a TERM-ignoring child. The real-wrapper regression failed before the budget repair and passed afterward (measured, n=1 HUP case with a TERM-ignoring fake child and configured kill wait longer than the old adapter timeout). The same orphan was reproduced while the real wrapper was inside handoff grace, then fixed by including grace in the budget (measured, n=1 additional RED-to-GREEN case; selected phase × TERM behavior × HUP triple, t=3 INFERENCE, not an exhaustive lifecycle matrix). Budget arithmetic covers all configured wait-factor combinations in its bounded fixture (measured, n=16 combinations; t=4 is INFERENCE), with separate invalid/non-finite checks before launch. Additional offline checks cover control-endpoint authentication, per-child settings validation and refusal of historical main-model inference. These use fake backends/children; no live gate was repeated and they do not establish real TUI behavior or Linux execution.

Earlier post-grace offline validation, before the installer-alias correction, passed on the unchanged corrected runtime at that checkpoint (measured, n=5 sequential npm commands): Copilot n=37 tests with proxy present and n=37 absent, Node n=947, OpenAI n=21 including n=1 intentional native-lifecycle skip with proxy absent, and Auto n=119/n=23/n=40 across its suites. No failures or Python errors remained; no other skips were reported. Copilot lifecycle tests execute fake hosts, even when the real proxy is on PATH. The initial Node attempt used an incorrect in-repository TMPDIR (measured, n=9 failing tests of n=947); restoring ordinary OS temp outside repository/package scope made every previously failing test pass, without source changes. These earlier offline results do not upgrade the pre-correction real-client baseline to current live validation; at that checkpoint, production installation/verify/interactive handoff and Linux CI remained unrun.

Measured on 2026-11-02 after the installer-alias correction: focused alias/ownership checks passed (n=4 test methods), Copilot passed (n=38 tests) and Node passed alone (n=947 tests). The earlier proxy-present/absent integration and OpenAI/Auto counts predate this correction. These local checks are offline evidence, not production installation/interactive handoff or Linux CI evidence. Publishing the plugin does not update the installed launcher; that still requires the explicit installer and a new session.

`verify` requires a successful exit, success JSON without is_error, exact sentinel, nonempty session_id, exact selected modelUsage and an accepted successful guard request. Failure never refreshes the private success report. A retained report records a past check, not present health.
